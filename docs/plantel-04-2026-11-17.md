# BE-PLANTEL-04: OVR y cobertura

La consulta de integrantes selecciona membresías activas. La vista solicita el OVR individual por integrante y calcula una media de presentación: incluye cero válido, excluye valores ausentes y fallos, muestra cuántos integrantes fueron valorados y promedia por separado las posiciones disponibles. No persiste un OVR oficial ni una instantánea histórica.

La prueba local con datos simulados usa OVR 80 y 0, más un error 500: media 40, cobertura 2 de 3, promedio de posición 40 y error visible. La suite dirigida del plantel pasó 12 pruebas. No verifica el conjunto de integrantes ni las calificaciones reales.

El DTO de integrantes activos del backend conserva un valor de respaldo 65 cuando no hay OVR calculado. La vista actual obtiene el OVR del endpoint individual y no usa ese respaldo en la media. Otros consumidores podrían interpretarlo como una valoración real; revisar el contrato y compatibilidad antes de cambiarlo.

El usuario confirmó que existe una cuenta de prueba, pero no tiene sesión abierta y pidió dejar pendiente la comprobación si no se puede iniciar. Pendiente iniciar sesión de forma segura, identificar versión desplegada, contrastar integrantes activos y ratings contra la API, y guardar evidencia. No se consultaron datos reales ni se desplegó.
