# BE-PLANTEL-03: reglas y verificación

El agregado se basa en `PlayerHistory` de partidos en estado FINALIZADO. El cierre crea historial para participantes confirmados que tienen equipo y posición, y registra goles/asistencias de eventos confirmados por ambos lados. Los datos antiguos se usan tal como están registrados; no se ha auditado cada participación histórica. El equipo corresponde al registrado en el partido y la trayectoria comprende todos los equipos.

El endpoint existente de integrantes activos requiere autenticación JWT. La política actual permite su lectura a cualquier usuario autenticado; no exige pertenecer al equipo. Se mantiene el contrato compatible: campos opcionales, cero cuando hay historial con cero y null cuando no existe historial para el alcance. Un fallo del endpoint muestra error y reintento, no una lista vacía.

Verificación local: pruebas de servicio de cierre incluyen jugador sin confirmar y gol sin ambas confirmaciones; pruebas de repositorio H2 cubren dos equipos, cero, ausencia y exclusión de partido invalidado; pruebas MVC cubren el contrato; prueba con configuración de seguridad comprueba rechazo sin sesión. En frontend, pruebas del plantel cubren error/reintento y promedio con cero y valores ausentes. No se modificaron datos, permisos ni producción. Beta y PostgreSQL no se comprobaron.
